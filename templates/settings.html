The quick-create button above fills in your External ID automatically and opens the AWS console. The template is public and auditable.

Or set up manually:

  1. In your AWS account, go to IAM → Roles → Create Role
  2. Select "Another AWS account" as the trusted entity
  3. Enter our AWS Account ID: {{ platform_aws_account_id }}
  4. Check "Require external ID" and enter the same External ID as above
  5. Attach our least-privilege policy: read-only (recommended start — metadata only, never your data) or management (full agent capability, no IAM writes, no secret values)
  6. Copy the Role ARN and paste it above

The role's trust policy should look like:

{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": { "AWS": "arn:aws:iam::{{ platform_aws_account_id }}:root" },
    "Action": "sts:AssumeRole",
    "Condition": { "StringEquals": { "sts:ExternalId": "your-external-id" } }
  }]
}

No access keys ever leave your account. The platform assumes the role for short-lived temporary credentials (1 hour), and you can revoke access at any time by deleting the role.

How to get AWS credentials:

  • Sign in to the AWS Management Console
  • Go to IAM → Users → select your user
  • Under "Security credentials", create an access key
  • Attach appropriate policies (e.g., PowerUserAccess, ReadOnlyAccess)

Note: access keys are long-lived secrets. We encrypt them at rest, but IAM Role ARN is the safer option — consider switching when you can.
