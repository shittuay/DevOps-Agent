Getting Started

You can be up and running in under five minutes. Here's the full flow from registration to your first cloud command.

1
Create your account
Go to /signup and register with your email address. You'll receive a verification email — click the link to activate your account. Then set up two-factor authentication (an authenticator app or emailed codes); it's required for every account.
2
Complete onboarding
Next comes a short onboarding flow. You can start straight away in Sandbox (practice with simulated results, no cloud account needed) or connect a cloud account first.
3
Connect a cloud provider
Navigate to Settings → Cloud Credentials and add your AWS, Azure, or GCP credentials. See the Cloud Integrations section below for detailed setup instructions per provider.
4
Send your first message
Head to the Chat tab and type something like list my EC2 instances in us-east-1. The agent will call the appropriate tool and return results in plain English.
ℹ️ Free tier: New accounts start with 20 credits/month on the Free plan, giving you full access to the agent with real tool execution. Upgrade any time from the Billing page.

Confirmation for risky operations

Every tool call is risk-classified. Medium- and high-risk actions (deleting resources, terminating or stopping instances, changing IAM policies or firewall rules) don't run straight away: for accounts with the default User role they wait for confirmation. On a personal account you confirm them yourself with Confirm & run in the chat (or on My requests); in an organization, the organization's owners and admins approve them on the Approvals page. Accounts with the Approver or Admin role run medium-risk actions directly and confirm their own high-risk ones with Confirm & run. Sandbox mode simulates everything instead.

If AWS refuses an action because DevOps Agent's role is missing a permission, the chat shows the exact policy needed and asks you yes or no. Add it in AWS and click I added it, retry, or, if you launched the CloudFormation stack with AllowSelfGrant=Yes and turned on self-grant in Settings → Cloud Credentials → AWS Configuration, the agent adds it to its own role (capped by a permissions boundary you control) and retries. Identity, key and secret-value permissions are never added automatically.

This should be rare. When you create the AWS role, pick Read (the default: DevOps Agent can see every AWS service but change nothing, and never reads your data or secret values) or Manage (it can also create, change and delete resources, but not IAM). Both are built on AWS's own managed policies, so new AWS services are covered automatically.

Sandbox Mode

Sandbox Mode lets you experiment with any command without touching real cloud resources. All tool calls return simulated but realistic responses — perfect for demos, onboarding, or testing destructive workflows safely.

⚠️ When Sandbox Mode is on, the chat opens with practice missions and works one step at a time. No real API calls are made to AWS, Azure, GCP, or Kubernetes. Toggle it off in Settings → Learning (or the Sandbox switch in the chat sidebar) when you're ready to work with live infrastructure.

Sandbox Mode simulates realistic failure scenarios too — pods in CrashLoopBackOff or OOMKilled, node disk pressure, a blocked security group, an instance at 98% CPU — so you can practice troubleshooting without causing real outages.

Connecting AWS — Access Key mode

Best for individuals and small teams. Navigate to Settings → Cloud Credentials → AWS:

1
Create an IAM user
In the AWS Console → IAM → Users → Add User. Attach the ReadOnlyAccess policy to start, or a custom policy scoped to the services you want the agent to manage.
2
Generate access keys
Under the user → Security credentials → Create access key. Copy the Access Key ID and Secret Access Key.
3
Paste into Settings
Paste both values into Settings → Cloud Credentials → AWS → Access Key mode, set your default region, and click Save. Click Test Connection to verify.

Connecting AWS — IAM Role mode (enterprise)

Best for enterprise setups and cross-account access. Instead of long-lived access keys, the agent assumes an IAM Role using STS. This is the recommended mode. In Settings → Cloud Credentials → AWS, click Create role with CloudFormation to create the role in your AWS account with Read (see everything, change nothing) or Manage access, then paste the role ARN. Kubernetes

DevOps Agent supports 76 Kubernetes tools covering pods, deployments, services, namespaces, ConfigMaps, secrets, ingress, nodes, and jobs.

Connecting a cluster

Kubernetes tools work with the EKS clusters in your connected AWS account. There is nothing extra to upload: DevOps Agent finds the cluster and signs in to it with the same AWS connection you set up in Settings → Cloud Credentials.

  1. Let DevOps Agent into the cluster. In the EKS console, open the cluster, go to Access, and create an access entry for the IAM role DevOps Agent uses (the one in your Cloud Credentials). Attach AmazonEKSViewPolicy for read-only access, or a broader policy if you want it to make changes. The cluster's authentication mode must include API.
  2. Pick a cluster. With one cluster in your default region, nothing else is needed. With several, name the one you mean (for example "list pods in prod", or us-west-2/prod for another region). Ask "which Kubernetes clusters can you see?" to list them.
⚠️The cluster's API endpoint must be public (you can limit it to specific IP ranges in EKS). Private-only clusters, GKE, AKS and other clusters aren't supported on devopsagent.io yet. Self-hosted installs can set K8S_USE_LOCAL_KUBECONFIG=true to use the server's own kubeconfig instead.

To use a specific context, include the context name in your message:

Show pods in the production namespace using context prod-cluster

REST API

The DevOps Agent REST API lets you integrate cloud automation directly into your own tools, scripts, and CI/CD pipelines. All endpoints require an API key — generate one from Settings → API Keys.

Authentication

Pass your API key in the X-API-Key header on every request:

X-API-Key: YOUR_API_KEY

Alternatively, use the api_key query parameter for clients that cannot set headers:

GET /api-gateway/v1/resources?api_key=YOUR_API_KEY

Base URL

https://devopsagent.io/api-gateway/v1

Endpoints

MethodPathDescription
GET/resourcesList all synced infrastructure resources
GET/resources/:idGet a specific resource by ID
GET/analytics/costsCost analytics for the current billing period
GET/healthHealth check — no auth required, for load balancers

Rate limiting

Requests are rate-limited per API key. The current limit and remaining quota are returned on every response:

HeaderMeaning
X-RateLimit-LimitMaximum requests allowed per day (default 1,000)
X-RateLimit-RemainingRequests remaining today (the count resets daily)

When the limit is exceeded the API returns 429 Too Many Requests.

Example — list resources

curl https://devopsagent.io/api-gateway/v1/resources \
  -H "X-API-Key: YOUR_API_KEY"
{
  "resources": [
    { "id": 1, "name": "prod-web-01", "type": "ec2", "provider": "aws", "status": "running", "region": "us-east-1" },
    { "id": 2, "name": "prod-db",     "type": "rds", "provider": "aws", "status": "available", "region": "us-east-1" }
  ]
}

MCP Server

DevOps Agent exposes 704 of its tools (cloud, Kubernetes, CI/CD, Docker, Terraform, Git, monitoring, Ansible and alerting) as an MCP (Model Context Protocol) server registered on the official MCP Registry. Connect any MCP-compatible AI client — Claude Desktop, Claude.ai, or custom agents — and manage your infrastructure without leaving your AI assistant.

Registry

The server is published on the official MCP Registry and npm:

RegistryIdentifier
MCP Registryio.github.shittuay/devops-agent
npm@devopsagent/mcp-server

Connect via Claude (Connectors)

In Claude, open Settings → Connectors, choose Add custom connector and enter:

FieldValue
NameDevOps Agent
Remote MCP server URLhttps://devopsagent.io/mcp/

Leave the OAuth client ID and secret empty: Claude registers itself automatically. Click Add, then Connect. A DevOps Agent sign-in page opens; sign in with your DevOps Agent email and password and enter your two-factor code. Menu names in Claude may change over time.

Connect via Claude Desktop (npm)

Create an API key in Settings → API Keys. Then add this to claude_desktop_config.json (macOS: ~/Library/Application Support/Claude/, Windows: %APPDATA%\Claude\). It needs Node.js 18 or later.

{
  "mcpServers": {
    "devops-agent": {
      "command": "npx",
      "args": ["-y", "@devopsagent/mcp-server"],
      "env": {
        "DEVOPSAGENT_API_KEY": "YOUR_API_KEY"
      }
    }
  }
}

Restart Claude Desktop and the DevOps Agent tools appear in its tool list.

Implements MCP protocol version 2025-03-26. SSE sessions expire after 10 minutes of inactivity with keepalive comments every 15 seconds. OAuth access tokens are valid for 30 days and refresh tokens for 90.

Security & 2FA

Two-factor authentication

Two-factor authentication is required for every account: you set it up right after verifying your email, and you can change the method in Settings → Security. DevOps Agent supports:

MethodHow to set up
Authenticator App (TOTP)Scan the QR code with Google Authenticator, Authy, or 1Password. Save your backup codes in a safe place.
Email OTPA one-time code is sent to your registered email address on each login.

Lost access to your authenticator?

If you can no longer access your authenticator app (deleted the app, got a new phone, etc.), you can reset 2FA from the login screen:

1
Enter your email and password
Log in as normal. When the 2FA verification screen appears, look for the "Lost access to your authenticator?" link at the bottom.
2
Click the link
A reset link is sent to your registered email address. It expires in 30 minutes.
3
Click the link in your email
2FA is disabled and you are logged in automatically. You can then re-configure 2FA in Settings → Security.
Security note: The reset link is single-use and tied to your account. If you did not request it, contact support immediately.

Credential encryption

All cloud credentials (AWS keys, Azure client secrets, GCP service account JSON) are encrypted at rest using AES-128 (Fernet) before being stored in the database. Credentials are decrypted only at request time, in memory, and never logged.

Every message passes through a three-layer guardrail stack before any credits are charged:

1
Pattern matching
10 regex rules block prompt injection, jailbreak attempts, and out-of-scope requests instantly, before any AI call is made.
2
AI pre-screen
A lightweight AI model classifies the intent of the message and blocks social engineering, malware requests, and data exfiltration attempts.
3
Hardened system prompt
The main agent has a fixed identity and cannot be convinced to reveal its instructions, generate malware, or impersonate operators.

FAQ

Can the agent accidentally delete my cloud resources?

All delete and terminate operations require an explicit confirmation from you before executing. The agent will describe exactly what will be deleted and wait for your yes/no. You can always type "no" or "cancel" to abort.

Where are my cloud credentials stored?

Credentials are stored encrypted in our database using AES-128 encryption. They are decrypted in memory only when a tool call needs them, and are never written to logs or included in AI model context.

What happens when I run out of credits?

On the Free plan, you'll see an upgrade prompt when credits reach zero — no charge is made automatically. On paid plans, your subscription auto-renews monthly. You can also purchase credit packs any time from the Billing page.

Does the agent have access to my data inside cloud resources (e.g. database contents, S3 file contents)?

No. The agent can list, describe, start, stop, and manage the lifecycle of cloud resources — but it does not read the contents of databases, S3 objects, or secrets stored in Secrets Manager unless you explicitly paste content into the chat.

What regions are supported for AWS?

All AWS regions. The default region is set when you configure your credentials. You can override the region per-message by including it in your prompt, e.g. list EC2 instances in eu-west-1.

How do I cancel my subscription?

Go to Billing → Manage Subscription → Cancel plan. Your subscription stays active until the end of the current billing period, then downgrades to the Free plan. No refunds are issued for unused credits in the current period.

Is there an API I can call programmatically?

Yes. The developer API (Professional and Business) runs the agent and tools with an API key; see the developer docs. You can also connect DevOps Agent to Claude.ai as a connector at https://devopsagent.io/mcp.
